
1. site-packages 里有没有残留的 tilelang 包目录或独立 tvm:

ls /usr/local/python3.11.0/lib/python3.11/site-packages/ | grep -iE "tilelang|^tvm|tvm_ffi"
ls -la /usr/local/python3.11.0/lib/python3.11/site-packages/tilelang/ 2>/dev/null

判读:editable 模式正常应只有 tilelang-*.dist-info、_editable_skbc_tilelang.pth、_editable_skbc_tilelang.py;如果出现 `tilelang/lib/*.so` 或 `tilelang/lib/libtvm_*.so`,那就是残留拷贝,删掉它。

2. 动态库搜索路径里有没有多个含 tilelang/tvm 的目录(最容易踩的坑):

echo "$LD_LIBRARY_PATH" | tr ':' '\n' | grep -iE "tilelang|tvm|ascend|cann"

判读:如果同时出现 /home/zwh/tilelang-tileir-ascend/build/lib 和某个 site-packages / CANN 目录里也带 libtvm* 或 libtilelang* ,加载器就可能把两份不同文件都 dlopen 进来 → 重复注册。

3. 直接抓运行时到底 dlopen 了哪些库(最实锤):

cd /home/zwh/tmp && LD_DEBUG=libs python -c "import tilelang" 2>&1 | grep -iE "tilelang|libtvm" | head -60

判读:abort 之前会打印两次 calling init / 两个不同路径的 libtvm_compiler.so(或 libtilelang.so),那两行路径就是冲突源。

4. 顺手确认 PYTHONPATH 来源(sys.path 里有 `/home/zwh`,多半是环境脚本加的):

echo "$PYTHONPATH" | tr ':' '\n'

把这几条的输出发给我,尤其是第 2、3 条的路径列表,我就能告诉你删哪个、留哪个。我目前判断最可能的是:昇腾环境脚本(或历史遗留 export)把某个带 `libtvm*`/`libtilelang*` 的目录塞进了 `LD_LIBRARY_PATH`,而它和你源码树 build/lib 里那份是不同文件,于是被加载了两次。
