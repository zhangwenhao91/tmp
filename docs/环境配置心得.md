# TileLang Ascend IR 环境配置心得

本文记录在 WSL/Linux 环境中运行 `examples/ascend/vadd_demo.py`，并通过
`tilelang.lower(program, target="tile")` 得到下降后 IR 的过程、问题和解决方法。
内容包含上一个 agent 的排错总结，以及当前环境中已经验证成功的运行命令。

## 一、目标和结果

`vadd_demo.py` 的入口是：

```python
program = vadd()
tilelang.lower(program, target="tile")
```

运行成功后，标准输出中会包含：

1. TileLang/TIRX 下降后的 IR，例如 `@I.ir_module`、`@T.prim_func`、
	 `T.sblock`、`T.alloc_shared`、`T.copy`、`T.vadd` 和线程绑定信息。
2. 后续的 MLIR codegen 输出，例如 `memref`、`arith`、`scf`、`linalg` 等方言。

当前已经验证生成的桌面文件为：

```text
/mnt/c/Users/lly/Desktop/vadd_demo_lowered_ir.txt
```

该文件曾验证包含 `@I.ir_module`，共 159 行、9587 字节。

## 二、当前环境组成

- 操作系统环境：WSL/Linux
- 项目目录：`/home/lly/helloworld/tilelang-tileir-ascend`
- Python 虚拟环境：项目根目录下的 `.venv`
- 本地 TileLang Python 源码：项目根目录下的 `tilelang/`
- 本地 TVM Python 源码：`3rdparty/tvm/python`
- 本地构建动态库：`build/lib/`
- 本地 tvm-ffi 构建目录：`3rdparty/tvm/3rdparty/tvm-ffi/build/lib/`

项目的 `tilelang/env.py` 在检测到开发源码布局时，会把开发根目录下的
`build/lib` 和 `build/tvm` 加入库搜索路径。因此运行源码时，不能只依赖
PyPI 中安装的 TileLang；应优先确保当前目录、源码目录和本地动态库都指向
这份 checkout。

## 三、已经验证的运行方式

先进入项目根目录并启用 `.venv`：

```bash
cd /home/lly/helloworld/tilelang-tileir-ascend
source .venv/bin/activate
```

设置本地库和 Python 搜索路径：

```bash
export TVM_LIBRARY_PATH="$PWD/build/lib"
export PYTHONPATH="$PWD:$PWD/tilelangir:$PWD/3rdparty/tvm/python${PYTHONPATH:+:$PYTHONPATH}"
export LD_PRELOAD="$PWD/3rdparty/tvm/3rdparty/tvm-ffi/build/lib/libtvm_ffi.so"
```

运行并在控制台查看 IR：

```bash
python examples/ascend/vadd_demo.py
```



看到 `@I.ir_module` 且 Python 退出码为 `0`，即可确认 vadd 下降成功。

## 四、最关键的问题：重复加载 libtvm_ffi.so

### 现象

最初运行时遇到类似以下错误：

```text
TypeAttr already registered
```

或者在导入 TVM/TileLang 相关模块时直接崩溃。

### 根因

进程中同时加载了多份不同来源或不同版本的 `libtvm_ffi.so`。例如：

- PyPI 环境中的 tvm-ffi 动态库；
- `build/lib/libtvm_ffi.so`；
- `3rdparty/tvm/3rdparty/tvm-ffi/build/lib/libtvm_ffi.so`。

这些库都注册 TVM FFI 类型。多个版本同时进入同一个进程后，会发生类型
重复注册，最终表现为 `TypeAttr already registered` 等错误。

### 解决方法

 agent 采取了以下处理：

1. 使用仓库中的 `3rdparty/tvm/3rdparty/tvm-ffi/` 构建本地 tvm-ffi；
2. 用本地构建版本替代 PyPI 版本，避免 ABI 或注册表不一致；
3. 检查各个搜索路径中的 `libtvm_ffi.so`，让它们统一指向同一个规范文件；
4. 运行时通过 `LD_PRELOAD` 优先加载该规范文件。

当前推荐的规范文件是：

```text
/home/lly/helloworld/tilelang-tileir-ascend/3rdparty/tvm/3rdparty/tvm-ffi/build/lib/libtvm_ffi.so
```

不建议在同一次运行中混用 PyPI tvm-ffi 和仓库本地构建的 tvm-ffi。若再次
出现类型重复注册，优先检查动态库实际加载情况，而不是修改 vadd 算子本身。

## 五、`tilelang_cython_wrapper` 导入问题

### 现象

排除重复动态库问题后，曾遇到：

```text
ModuleNotFoundError: No module named 'tilelang_cython_wrapper'
```

### 根因

当前源码环境没有成功生成或安装 TileLang 的 Cython 扩展模块。仓库的构建
配置中确实包含 `tilelang_cython_wrapper` 目标，但如果只使用源码路径运行，
扩展可能没有位于当前 Python 的可搜索路径中。

###  agent 的处理

agent 创建了一个 `tilelang_cython_wrapper.py` stub，使相关导入能够
继续进行，并成功得到 vadd 的 IR 输出。

从长期维护角度看，更正规的办法是完成项目的 CMake 构建，生成真正的
`tilelang_cython_wrapper` 扩展，并让它位于 Python 可搜索路径中。stub 是本次
排错中使用的临时兼容措施，不应在需要完整运行时功能时替代真正的 Cython
扩展。

## 六、曾经遇到的命令行问题

### 1. `rg` 不存在

当前环境中 `rg` 可能没有安装，搜索时可以使用：

```bash
grep -R -n -E '关键字1|关键字2' tilelang examples testing
```

这不会影响 TileLang 运行本身。

### 2. 运行命令回显被终端换行打乱

较长的 export 和重定向命令在终端回显中可能被拆成多行，但不代表命令
一定失败。应通过退出码和输出文件内容确认：

```bash
echo $?
grep -n -m1 '@I.ir_module' /mnt/c/Users/lly/Desktop/vadd_demo_lowered_ir.txt
```

## 七、agent 的总结

 agent 的最终结论如下，保留在这里便于以后复现：

- PyPI TileLang 缺少 Ascend API，不能提供 `SimdVF`、`vadd` 和
	`target="tile"` 所需能力，因此使用本地源码；
- `TypeAttr already registered` 的根因是进程加载了 3 份不同版本的
	`libtvm_ffi.so`，解决办法是构建本地 tvm-ffi，并让所有副本统一软链接到
	同一个规范文件；
- `No module named 'tilelang_cython_wrapper'` 的根因是 Cython 扩展未编译，
	当时通过 stub 模块满足导入；
- 配好环境后，`tilelang.lower(program, target="tile")` 成功输出了 TileLang
	Lowered IR 和 MLIR Codegen；
- 运行时使用本地源码和下面三个关键环境变量：
	`TVM_LIBRARY_PATH`、`PYTHONPATH`、`LD_PRELOAD`。

上一个 agent 还提到过 `run_demo.sh`，但当前 checkout 中未发现该脚本。因此
目前应以本文第三节的手动命令为准；手动命令能明确显示实际使用的 Python、
动态库和源码路径。
